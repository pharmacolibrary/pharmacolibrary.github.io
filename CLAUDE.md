# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

The static Docsify site for Pharmacolibrary (popPK/PD/PGx models extracted from literature, plus toxins). It is a **site shell plus generated content**, not an app with a build step. Deployed by mirroring to the `pharmacolibrary.github.io` repo. `CONTRIBUTING.md` is the authoritative maintainer guide; read it before structural changes.

## Generated vs. authored — the key rule

Most of the ~84k tracked files are **generated by the sibling repo `~/Projects/pharmacolibrary-dev`** (`pk_knowledge_scripts/docs/`: `build`, `ledger.py`, `build_set.py`, `nav.py`, `refresh_text`). Do not hand-edit them; fix the generator or source records instead:

- Generated: `drugs/`, `toxins/`, `atc/`, `ledger/`, `review/`, `_sidebar.md`, `.index.json`, `pipeline.md`, `data/*.sqlite`, `models/`, `assets/fmu/`, and everything between `<!-- AUTOGEN:... START/END -->` markers (README.md, ledger.md). The generator preserves text outside marked regions.
- Authored here: `index.html` (markup only), `assets/js/*`, `assets/css/*`, `README-template.md` (source of the README intro region — edit it, not README.md), `query.md`, `sites.md`, `graph.md`, `data.md`, `CONTRIBUTING.md`, `scripts/`, `tests/`, `tools/`.
- Sibling repos: `dbs-components-dev` (component source), `dbs-components` (releases). Never hand-copy or edit a `dbs-*` component here; fix upstream, rebuild, re-import (see below).
- `README.md.backup` and `plan-*.md` are design notes, not site content.
- Large untracked `drugs/toxin_*` dirs in `git status` are normal generator output.

## Commands

```bash
python3 -m http.server 8765                 # preview at http://localhost:8765
python3 scripts/check-site.py               # shell integrity: HTML rules, module load order, component hashes, node --check on assets/js/*.js, generated-page budget
python3 scripts/check-site.py --generated   # only the generated-page size check (2.5 MB per page budget for ledger/, review/)
node --test tests/components-loader.test.cjs
python3 -m unittest tests/test_component_import.py   # component importer
python3 scripts/update-components.py ../dbs-components   # import a pinned component release -> components.lock.json
./sync-to-pages.sh [dest]                   # rsync --delete into ~/Projects/pharmacolibrary.github.io (preserves its .git)
```

Browser tests (`tests/*.cjs`: `browser-smoke`, `sites-style`, `sites-view`, `sidebar`, `pgx-curated-baseline`, `ddd-diagrams`) need Playwright + Chromium installed under `/tmp/opencode/site-check`, a running preview server, and are run as e.g. `NODE_PATH=/tmp/opencode/site-check/node_modules node tests/sidebar.cjs`. `SITE_URL` overrides the origin. Each file is a standalone script; run one directly to run a single test.

`tools/graph-proxy/` is a Cloudflare Worker (`wrangler`) proxying named read-only Neo4j queries for `/graph`; its tests are `node tools/graph-proxy/test.mjs`.

## Architecture

**Shell (`index.html` + `assets/js/pk-*.js`).** `index.html` has no inline `<script>`/`<style>` (check-site.py fails otherwise). Each behavior lives in exactly one deferred module, and **script order in `index.html` is behavior** (Docsify hooks register in document order). `check-site.py`'s `MODULE_ORDER` pins it: `docsify-config.js` first, `pk-legacy-routes.js` early (redirects old `#/ledger`, `#/review` before Docsify fetches), `docsify-sidebar-collapse.min.js` before `pk-sidebar-state.js`, `pk-components-loader.js` last. Adding or reordering a module means updating both `index.html` and `MODULE_ORDER`. The module table in `CONTRIBUTING.md` lists each module's job. If a module and any inline copy differ, the module wins.

**Routing.** All routes are `#/…` hash routes over Markdown files (`#/drugs/drug_x/record`, `#/atc/C10A`, `#/sites`, `#/query`, `#/graph`, `#/data`). The home route (`pk-cover.js`) hides the sidebar. Record pages are sliced into tabs at build-emitted sentinels (`pk-record-tabs.js`, `?tab=` deep links).

**Generator↔frontend contracts** (change both sides together): `.pk-tab-mark` / `.pk-tab-end`, `.pk-crumbs[data-crumbs]`, `.pk-recnav[data-items]`, `.pk-model-meta[hidden]`.

**Data.** In-browser SQLite (sql.js, `assets/sqljs/`) via `pk-db.js`; database URLs resolve through `data/*latest.json` (so content updates never change the shell). Query/Ask engines (`pk-ask.js`, `pk-ask-llm.js`), simulators (`pk-sim.js`) and the sites anatomogram (`pk-sites.js`) are fetched on demand.

**Simulation.** FMU/WASM model exports in `assets/fmu/` and `models/`, run by `<dbs-fmusim>` loaded lazily by `pk-components-loader.js` from the content-addressed release under `assets/vendor/dbs-components/<sha>/`, pinned by `components.lock.json` (hash-verified by check-site.py).

**Page-size budget.** No generated page may exceed 2.5 MB; oversized units get split into new pages (hence the sharded `ledger/` and `review/` dirs, with `ledger.md`/`review.md` as stubs for old links).

## Conventions worth knowing

- Scientific numbers/downloads are pipeline outputs: correct the source record upstream, never the generated number here.
- Presentation CSS for ledger pages lives in `assets/css/ledger.css`, synced with the generator via `scripts/migrate-presentation.py`.
- Data is research-only; a disclaimer banner is injected on drug/record/Sites routes (`pk-disclaimer.js`).
